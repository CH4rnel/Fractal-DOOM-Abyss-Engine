# SCRIPTURE I :: THE BEGINNING

Fractal DOOM is an experimental game engine built around one forbidden idea:

> **What if the mathematics generating the world was the world?**

Traditional games construct reality from meshes, textures, maps and predefined geometry.

Abyss Engine takes another route.

```text
Traditional Game

MAP
 │
 ├── Geometry
 ├── Textures
 ├── Entities
 └── Scripts
      │
      ▼
    WORLD
```

```text
ABYSS ENGINE

MATHEMATICS
     │
     ▼
 FRACTAL SPACE
     │
     ├── Geometry
     ├── Environment
     ├── Entities
     ├── Anomalies
     └── Gameplay
          │
          ▼
        WORLD
```

There are no handcrafted corridors waiting for the player.

There is only a mathematical space being evaluated.

The deeper you go, the more of it becomes visible.

And eventually...

the mathematics begins to fight back.

# SCRIPTURE III :: THE LAWS

## ABYSS PROTOCOL I

> **Everything must be deterministic.**

A universe must be reproducible.

Given the same:

```text
SEED
+
COORDINATES
+
DEPTH
+
WORLD STATE
```

the engine must be capable of reconstructing the same reality.

---

## ABYSS PROTOCOL II

> **The GPU computes reality.**

The CPU controls simulation.

The GPU evaluates the mathematical universe.

The goal is not to generate millions of polygons and pretend they are infinite.

The goal is to calculate what exists where it is needed.

---

## ABYSS PROTOCOL III

> **Mathematics must influence gameplay.**

A fractal that merely looks pretty is insufficient.

The equation must influence:

- movement
- exploration
- combat
- enemies
- resources
- bosses
- sound
- progression
- world events

---

## ABYSS PROTOCOL IV

> **A boss is not an enemy.**

A boss is a corruption of mathematics.

When the boss changes phase, the world itself may change.

---

## ABYSS PROTOCOL V

> **Crypto is not the game.**

Blockchain functionality must remain an external integration layer.

The engine must remain playable without it.

The game comes first.

Always.

The first generation of the engine will explore several mathematical families.

```text
┌───────────────────────────────────────────┐
│ FRACTAL CORE                              │
├───────────────────────────────────────────┤
│                                           │
│ Mandelbrot                               │
│ Julia                                    │

│ Iterative Systems                        │
│ Domain Warping                           │
│ Custom Recursive Functions               │
│                                           │
└───────────────────────────────────────────┘
```

Eventually the engine will support experimental hybrid formulas.

A world may begin as:

```text
z = z² + c
```

and mutate into something considerably less sane.

```text
z = z² + c + sin(z × t)
```

Later:

```text
z = F(z, c, t, entropy, player, world)
```

At that point the equation is no longer merely a renderer.

It becomes part of the simulation.

# SCRIPTURE XIII :: THE LORE ENGINE

Every world contains information derived from its mathematical state.

The lore system converts world metadata into narrative.

Example:

```text
WORLD #000000666

FORMULA       : JULIA
DEPTH         : 666
CORRUPTION    : 93%
BOSS          : THE RECURSOR
STABILITY     : 4%
```

becomes:

```text
THE RECURSOR

It was not born.

It was calculated.

At the six-hundred-and-sixty-sixth layer,
the equation stopped describing reality.

It began describing itself.

Something noticed.

Something answered.
```

The long-term goal is an AI-assisted narrative system that interprets deterministic world data.

The AI describes the universe.

It does not define its physics.

